Search emoji by name or keyword in the user's language, using CLDR annotations. Among the most-requested features in several open-source keyboards.

## Platform notes

Needs text entry inside the keyboard itself (a search field that captures keystrokes), which both platforms allow.

## Acceptance criteria

- [x] Emoji can be searched by name or keyword from inside the keyboard
- [x] The catalogue is every RGI emoji with CLDR names and keywords
- [x] The keyboard keeps its size while searching
- [ ] Keywords in languages other than English

## Tasks

- [x] Generate the catalogue from Unicode and CLDR data (scripts/generate-emoji-data.py)
- [x] Search and ranking in the engine
- [x] The strip turns into a query box and the letters type into it
- [x] Check on the Pixel and the simulator (test15_emojiSearch)

## Progress

The catalogue is now every RGI emoji (Unicode 15.1, 1,898 base emoji, 329 with skin tones flagged for the picker) with English CLDR 44 names and keywords, generated by scripts/generate-emoji-data.py and parsed on first use. Search: every typed word must start a word of the name or keywords; exact and name matches rank first, the most used emoji first within a tier ("heart" → ❤️, "+1" → 👍). In-keyboard search: the panel's search button turns the strip into a query box with scrolling results while the letters type into the query; the keyboard keeps its size. Picking a result types it and keeps the search open; Enter or the emoji key goes back to the panel. Verified on the Pixel 6 Pro and the iPhone 17 simulator (🍕 typed via "pizza"), 2026-09-28. Only English keywords so far.
